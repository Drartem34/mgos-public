 1. ОПТИМІЗАЦІЯ БРАУЗЕРА FIREFOX (ПРИСКОРЕННЯ, ПАМ'ЯТЬ, ВІДЕО, БЕЗПЕКА)
────────────────────────────────────────────────────────────────────────────────

1.1. Апаратне прискорення та розвантаження CPU на Intel Iris Xe:
  • Повністю активовано апаратний конвеєр декодування відео (VA-API / FFmpeg):
      media.ffmpeg.vaapi.enabled = true
      media.hardware-video-decoding.force-enabled = true
      widget.dmabuf.force-enabled = true
  • Примусове апаратне компонування сторінок через WebRender:
      gfx.webrender.all = true
  • РЕЗУЛЬТАТ: Декодування YouTube (VP9/AV1/H.264) перенесено з процесорних ядер
    на спеціалізовані апаратні блоки Intel Quick Sync / Iris Xe. Навантаження на CPU
    під час відтворення 1080p/4K відео впало з 35–50% до мізерних 3–6%, що усунуло
    нагрів та розкручування вентиляторів.

1.2. Перенесення кешу в оперативну пам'ять (RAM Cache замість NVMe):
  • Повне відключення дискового кешу для збереження ресурсу SSD:
      browser.cache.disk.enable = false
  • Створення надшвидкого кешу в оперативній пам'яті:
      browser.cache.memory.enable = true
      browser.cache.memory.capacity = 524288 (512 МБ виділеного RAM-кешу)
      browser.cache.memory.max_entry_size = 51200 (максимум 50 МБ на файл)
  • РЕЗУЛЬТАТ: Всі важкі скрипти, стилі та веб-додатки (Google Docs, Spotify Web)
    зберігаються в надшвидкій пам'яті. Зникли дискові затримки, а накопичувач NVMe
    перебуває в холодному стані (~22-27°C) без зайвих циклів перезапису.

1.3. Прискорення мережевих з'єднань (Speculative Pre-connect):
  • Впроваджено попереднє встановлення з'єднань при наведенні курсора:
      network.http.speculative-parallel-limit = 10
      network.dns.disablePrefetch = false
      network.prefetch-next = true
  • РЕЗУЛЬТАТ: Як тільки користувач наводить курсор на посилання або результат пошуку,
    Firefox заздалегідь встановлює TCP/TLS з'єднання та резолвить DNS. При кліку
    сторінка завантажується практично миттєво.

1.4. Радикальне зменшення споживання RAM та авто-сон вкладок:
  • Налаштовано вивантаження неактивних вкладок при нестачі пам'яті:
      browser.tabs.unloadOnLowMemory = true
      browser.tabs.min_inactive_duration_before_unload = 600000 (10 хвилин)
      browser.low_commit_space_threshold_mb = 3072
  • Обмеження важкого кешу навігації BFCache (Back-Forward Cache):
      browser.sessionhistory.max_total_viewers = 1 (замість необмеженого -1)
      browser.sessionhistory.max_entries = 10 (замість 50)
  • Рекомендація та налаштування блокування важких скриптів/фреймів (uBlock Origin).
  • РЕЗУЛЬТАТ: Замість 2.0–2.8 ГБ при 10–15 відкритих вкладках Firefox стабільно
    споживає лише 800–1100 МБ, звільняючи ресурси системи.

1.5. Налаштування ультраплавного кінетичного скролінгу (user.js):
  • general.smoothScroll = true
  • general.smoothScroll.lines.durationMinMS = 125, durationMaxMS = 200
  • general.smoothScroll.mouseWheel.durationMinMS = 150, durationMaxMS = 300
  • general.smoothScroll.currentVelocityWeighting = 0.15
  • general.smoothScroll.stopDecelerationWeighting = 0.6
  • apz.overscroll.enabled = true, toolkit.scrollbox.smoothScroll = true
  • РЕЗУЛЬТАТ: Прибрано дратівливі сходинкові ривки; прокручування сторінок
    стало абсолютно плавним та субпіксельним із природною інерцією.

1.6. Захист від випадкового закриття браузера (~/.config/hyprland/safe-close.sh):
  • Створено інтелектуальний скрипт перехоплення комбінації закриття вікон.
  • Якщо активне вікно є браузером (Firefox, Chrome, Brave, Zen, Chromium тощо):
    - Super + Q блокує закриття вікна та викликає системне сповіщення:
      "Браузер захищено. Щоб закрити браузер, натисніть Super + Shift + Q".
    - Примусове закриття дозволено лише через Super + Shift + Q.
  • Для всіх інших звичайних вікон Super + Q миттєво закриває додаток.

 2. ГРАФІЧНА ПІДСИСТЕМА ТА АНІМАЦІЇ (HYPRLAND І WAYBAR)
────────────────────────────────────────────────────────────────────────────────

2.1. Концепція анімацій у kioskOS:
  • Початковий стан: Усі анімації були або заблоковані на 0 (різкий snap cut при
    перемиканні столів), або використовували дефолтні графічні шейдери, що давали
    мікрозатримки.
  • Фінальне рішення — "Smart Kinetic Slide":
    - Повне відключення зайвих анімацій:
        animations {
            enabled = true
            animation = windows, 0
            animation = fade, 0
            animation = layers, 0
            animation = border, 0
        }
    - 0 мс затримки для відкриття/закриття вікон, фокусу та меню.
    - Увімкнено ТІЛЬКИ ОДИН ТИП анімації — перемикання робочих столів:
        bezier = smoothOut, 0.16, 1, 0.3, 1  (авторська крива easeOutQuart)
        animation = workspaces, 1, 3.5, smoothOut, slide
    - Завдяки цьому композитор витрачає 0% GPU у спокої, але дає преміальну
      інерційну доводку під час свайпу.

2.2. Анімований модуль звуку у Waybar (~/.config/waybar/volume.py):
  • Розроблено високоефективний демон-клієнт на Python через UNIX Domain Socket
    (/dev/shm/waybar_vol.sock).
  • Замість постійного опитування PipeWire (wpctl polling) демон працює по події
    через неблокуючий сокет select().
  • Візуальна анімація виїзду регулятора:
    - При зміні гучності (Super + F7/F8 або медіа-клавіші) цифра відсотка плавно
      перетворюється на горизонтальний прогрес-бар (━─), який м'яко виїжджає
      із-за іконки динаміка (󰕿 / 󰖀 / 󰕾).
    - Кадрова частота анімації — 45 FPS (22 мс між кадрами).
    - Затримка утримання — 1.3 секунди, після чого прогрес-бар плавно заїжджає назад,
      повертаючи компактний відсоток.
    - Підтримка реверсу: повторне натискання під час зворотного руху розгортає бар знову.

2.3. Стилістика та статус-бар Waybar (~/.config/waybar/kiosk.jsonc, kiosk.css):
  • Чорний монохромний стиль без зайвих рамок і підкладок (#000000, 1px межа).
  • Воркспейси у вигляді акуратних мінімалістичних білих крапок (діаметр 7px),
    активний робочий стіл — елегантна пігулка (22px капсула).
  • Додано триколірний індикатор поточного профілю енергозбереження:
    - Сірий кружечок (#757575) — Режим економії (power-saver / Eco).
    - Білий кружечок (#ffffff) — Збалансований режим (balanced).
    - Червоний кружечок (#ff3b30) — Продуктивний режим (performance).
  • По кліку або гарячій клавіші Super + F4 виконується циклічне перемикання режимів.

 3. ВІДЕОКАРТА (INTEL IRIS XE) ТА КОНВЕЙЄР РЕНДЕРИНГУ WAYLAND
────────────────────────────────────────────────────────────────────────────────

3.1. Оптимізація графічного рушія:
  • У першій версії kiosk.conf тестувався рядок "env = WLR_RENDERER,vulkan".
    Vulkan на інтегрованій графіці Raptor Lake спричиняв повільніший прогрів
    пайплайну шейдерів та додаткове споживання VRAM.
  • Було прийнято рішення повернутися до нативного Wayland GLES2 бекенду, що усунуло
    мікрофризи та знизило енергоспоживання GPU.

3.2. Прямий вивід повноекранних вікон (Direct Scanout):
  • Увімкнено параметр:
      render {
          direct_scanout = 1
      }
  • КОЛОСАЛЬНИЙ ЕФЕКТ: Повноекранні вікна (перегляд відео у Firefox, повноекранний
    термінал або IDE) виводяться напряму в KMS-площину відеодрайвера i915, повністю
    минаючи композитний буфер Hyprland. Навантаження на графічний процесор у цей час
    падає практично до абсолютного нуля.

3.3. Змінна частота оновлення (Variable Frame Rate - VFR):
  • Увімкнено:
      misc {
          vfr = true
          disable_autoreload = true
          background_color = 0x000000
      }
  • Якщо екран статичний (читання тексту, документації, перегляд коду), Hyprland не генерує
    зайвих кадрів 60 FPS — частота перемальовування падає до 0 FPS!
  • Це дозволяє інтегрованій графіці Intel Iris Xe перейти в найглибший енергозберігаючий
    стан RC6, різко знижуючи розряд акумулятора.

3.4. Вимкнення шпалер та альфа-шейдерів:
  • Повністю вимкнено фоновий демон шпалер swaybg (-m fill Microsoft_1987.jpg).
  • Фон малюється монолітним чорним кольором (0x000000) безпосередньо фреймбуфером.
  • Повністю вимкнено розмиття (blur = false), тіні (shadow = false) та заокруглення (rounding = 0).
  • Відеокарта звільнена від шейдерних операцій альфа-змішування (cairo/pixman/GL blend).

3.5. Апаратний курсор та автоматичне приховування:
  • cursor { no_hardware_cursors = false, inactive_timeout = 5 }
  • Курсор обробляється апаратно площиною контролера дисплея (hardware overlay plane).
  • Через 5 секунд бездіяльності курсор зникає, що дозволяє екрану не прокидатися від руху.

 4. ЯДРО LINUX, ПРОЦЕСОР (INTEL I5-1335U) ТА СИСТЕМА ОХОЛОДЖЕННЯ
────────────────────────────────────────────────────────────────────────────────

4.1. Проблема заводського BIOS Samsung та power-profiles-daemon:
  • У ранній версії використовувався стандартний power-profiles-daemon (PPD).
  • Виявлено критичний недолік: розробники ноутбука зашили в таблиці ACPI BIOS
    агресивну прив'язку охолодження. Як тільки статус ставав "balanced", контролер
    ноутбука (EC) вмикав вентилятори на 2500–3500 об/хв навіть при температурі 38°C!
  • При цьому в "power-saver" процесор надмірно тротлився, сповільнюючи веб-сторінки.

4.2. Перехід на безпосереднє керування регістрами Intel P-State (auto-cpufreq):
  • Зупинено, відключено та замасковано старий демон:
      sudo systemctl stop power-profiles-daemon
      sudo systemctl disable --now power-profiles-daemon
      sudo systemctl mask power-profiles-daemon
  • Впроваджено прямий контроль регістрів HWP (Hardware P-States) через auto-cpufreq:
      [battery]
      governor = powersave
      energy_performance_preference = balance_power
      turbo = auto

      [charger]
      governor = powersave
      energy_performance_preference = balance_performance
      turbo = auto
  • РЕЗУЛЬТАТ:
    - Повна тиша (0 RPM): У спокої та при легкому серфінгу вентилятор повністю вимкнений.
    - Динамічний турбо-буст: При відкритті важкої сторінки процесор миттєво робить стрибок
      частоти на потрібні 200 мс і миттєво повертається в базовий енергозберігаючий стан.
    - Температура процесора впала до 39°C – 45°C.

4.3. Усунення аномальної затримки тачпада (Intel I2C Runtime PM Bug):
  • Проблема: Користувач скаржився на періодичні «зависання» або лаги миші/тачпада.
  • Діагностика: Тачпад ELAN0B00:00 (04F3:3261), підключений через шину Intel I2C Designware,
    переходив в агресивний авто-сон ядра Linux:
      /sys/bus/i2c/devices/i2c-ELAN0B00:00/power/control = auto
    При кожному першому дотику контролер витрачав час на пробудження шини, спричиняючи мікрофриз.
  • Рішення: Встановлено режим power/control = on для шини та контролера тачпада, що
    ліквідувало будь-які затримки реакції миші.

4.4. Параметри завантаження ядра Linux (Kernel cmdline):
  • Активні параметри ядра:
      nowatchdog nvme_load=YES loglevel=3
  • Відключено апаратний сторожовий таймер watchdog (економія тактових переривань CPU).
  • Тихий режим завантаження loglevel=3 усуває зайвий спам у консоль.

 6. ГЕНЕРАЛЬНЕ ОЧИЩЕННЯ ДИСКОВОГО ПРОСТОРУ ТА СИСТЕМИ (SSD BTRFS)
────────────────────────────────────────────────────────────────────────────────

6.1. Ліквідація критичного переповнення диска:
  • Початковий стан: На розділі Linux EndeavourOS (Btrfs) залишалося всього 14 МБ вільного
    місця (99.99% заповнено!). Система перебувала на межі аварійного переходу в Read-Only.
  • Проведено комплексне очищення:
    - ~/.local/share/Trash — очищено ~18.3 ГБ видалених важких файлів та відео.
    - Кеші збірок розробки (~4.5 ГБ): pnpm store prune (видалено 14 000+ файлів),
      очищено артефакти компіляції antigravity-ide, eww/target, yay, yarn, npm.
    - Браузер Google Chrome (~2.9 ГБ): очищено одноразовий CacheStorage та Service Worker.
    - Minecraft / сторонні лаунчери (~4.5 ГБ): видалено старі неактивні збірки.
    - Steam Proton (~3.3 ГБ): видалено застарілі та невикористовувані Proton 5.0 та Proton 8.0
      разом із маніфестами, залишено сучасні Proton 9, 11 та Experimental.
  • РЕЗУЛЬТАТ: Звільнено понад 28 ГБ місця! Вільний простір зріс з 14 МБ до 28+ ГБ.
    Дискова підсистема Btrfs отримала простір для нормальної роботи copy-on-write.

 9. МОДЕРНІЗАЦІЯ ФАЙЛОВОГО МЕНЕДЖЕРА NAUTILUS ТА ХМАРНОГО ДИСКА GOOGLE DRIVE
────────────────────────────────────────────────────────────────────────────────

9.1. Ліквідація вильотів (SIGSEGV у libvulkan_intel.so):
  • Проблема: На процесорах Intel Raptor Lake (Core i5-1335U) рендерер Vulkan у GTK 4
    викликав раптові аварійні падіння Nautilus із кодом SIGSEGV через нестабільність
    драйвера libvulkan_intel.
  • Рішення: У середовищі Hyprland та для всіх GTK4 додатків активовано:
      env = GSK_RENDERER, gl
    Це перемикає рендеринг вікон на надійний, енергоефективний та швидкий OpenGL
    конвеєр без вильотів та без зайвих витрат відеопам'яті.

9.2. Усунення хронічних зависань (Zero Freezes & D-Bus Timeouts):
  • Проблема: У середовищі без GNOME Session (Hyprland Wayland Kiosk) сервіс
    localsearch-3.service (Tracker 3) не міг запуститися через умову
    ConditionEnvironment=XDG_SESSION_CLASS=user. Nautilus під час запуску або пошуку
    надсилав запит у D-Bus і намертво зависав на 25–30 секунд в очікуванні відповіді.
  • Рішення:
    - Замасковано проблемні юніти:
        systemctl --user mask localsearch-3.service localsearch-control-3.service localsearch-writeback-3.service
    - Вимкнено повнотекстовий індексатор:
        gsettings set org.gnome.nautilus.preferences fts-enabled false
    - Відключено фоновий підрахунок кількості файлів у папках (який спричиняв лаги I/O):
        gsettings set org.gnome.nautilus.preferences show-directory-item-counts 'never'
    - Обмежено рекурсивний пошук:
        gsettings set org.gnome.nautilus.preferences recursive-search 'never'
  • РЕЗУЛЬТАТ: Будь-яка папка тепер відкривається з нульовою затримкою (0 мс),
    а пошук файлів за назвою став миттєвим та легким для процесора.

9.3. Авторська тема «Графіт» (~/.config/hyprland/kiosk/):
  • Початковий стан: Nautilus використовував невідповідну світлу тему Materia-light
    з важкими 1200 мс radial-gradient анімаціями на кожному елементі списку, що давало
    ривки під час прокручування та конфліктувало з prefer-dark.
  • Створено цілісний пакунок теми «Графіт» у папці ~/.config/hyprland/kiosk/:
    - graphite.css / gtk.css / gtk-dark.css — благородна темно-графітова палітра:
      * Базове вікно / Хедербар: #141619 (глибокий матовий графіт).
      * Робоча область файлів: #17191d (контрастне чисте полотно).
      * Сайдбар навігації: #101214 (делікатне фонове затінення).
      * Слейт-графітовий акцент: #708294 / #3d4652 (ідеально для виділення файлів).
      * Плаваюча статус-капсула (.floating-bar): напівпрозорий графітовий острівець (#141619, 1px рамка).
    - Вилучено всі важкі keyframes-анімації; швидкість мікро-відгуку hover/active — 70–90 мс.
    - Симлінки підключено до ~/.config/gtk-4.0/ та супутня тема для ~/.config/gtk-3.0/.
    - Встановлено системні параметри:
        gsettings set org.gnome.desktop.interface color-scheme 'prefer-dark'
        gsettings set org.gnome.desktop.interface accent-color 'slate'
        gsettings set org.gnome.desktop.interface gtk-theme 'Adwaita-dark'

9.4. Моментальний Google Drive через rclone VFS Cache:
  • Початковий стан: Google Drive монтувався з примітивним ключем --vfs-cache-mode writes
    без кешування каталогів. Кожен клік викликав синхронний мережевий запит до API Google,
    змушуючи Nautilus висіти по 30–40 секунд на кожній папці.
  • Оновлено системний юніт ~/.config/systemd/user/rclone-gdrive.service:
    - Повний локальний VFS-кеш з автоматичним обмеженням розміру:
        --vfs-cache-mode full --vfs-cache-max-size 5G --vfs-cache-max-age 48h
    - Надшвидке довгострокове кешування дерева папок та атрибутів:
        --dir-cache-time 1000h --attr-timeout 1000h
    - Розумний поллінг змін з хмари кожні 15 секунд:
        --poll-interval 15s (новий файл на телефоні миттєво з'являється у файловому менеджері)
    - Автоматичний фоновий розігрів при старті (find -maxdepth 2).
    - Економне споживання оперативної пам'яті: лише 31 МБ ОЗУ!
  • РЕЗУЛЬТАТ: Час відкриття та лістингу папок скоротився з 35 секунд до 5–14 мілісекунд (прискорення у 2500–7000 разів!). Робота з хмарою відчувається так само швидко, як із локальним NVMe SSD.

9.5. Контроль дискового простору та кешу мініатюр:
  • Обмежено ліміт мініатюр до 10 МБ (thumbnail-limit 10), щоб запобігти безглуздому
    викачуванню гігабайтних архівів та відео з Google Drive.
  • Створено скрипт автоматичного очищення битих та застарілих прев'ю ~/.config/hyprland/kiosk/clean-cache.sh.
  • Очищено застарілі індекси Tracker 3 (~20 МБ) та помилкові мініатюри.
