## Спільний файл `~/.config/SYSui/pixel_waves.h` — правила

1. **Перед кожною правкою перечитай файл з диска.** Інший агент міг змінити його хвилину тому.
   Ніколи не перезаписуй файл цілком зі своєї старої копії — лише точкові вставки/заміни.
2. Нове — лише **додаванням**: свій `enum S_*` і назва в `N[]` — **в кінець** списку (і онови число в циклі
   `style_id()`), свій блок коду — перед коментарем `// Рівень пікселя для стилю`.
3. У `render()` кожна пара — **окремим рядком**:
   `if (sid == S_X) x_prepare(...);` і (якщо є буфери) наступним рядком `else if (!x_buf.empty()) {...звільнити...}`.
   Не вставляй рядок між чужим `if` і його `else` — так уже було падіння (segfault щокадру).
4. Файл має **компілюватися після кожної твоєї правки** — його читає інший агент і збирає свій код:
   `cd ~/.config/SYSui && ./build.sh pixel_wallpaper`. Не залишай напівготовий код у живому файлі —
   готуй у копії, вставляй готове.
5. Перевірка перед «готово»: постер кожного свого стилю в обох темах
   `./pixel_wallpaper --poster /tmp/x.png 400x224 --style ID --color '#c13cff' --theme dark|light`
   (код виходу 0, картинка не порожня), і що чужі стилі теж рендеряться (не зламав спільне).

## Реєстрація стилю (теж лише додаванням, в кінець)

- `~/.config/ignis/settings.py` → `PIXEL_STYLES_WP` (не `PIXEL_STYLES` — це ще й «шапки» панелей).
- `~/.config/SYSui/welcome.cpp` → масив `OPTS[]`; потім `./build.sh welcome`.
- Кеш прев'ю після зміни стилю: `rm -f ~/.cache/megumin-os/pixel_previews/<id>_*`.

## Готові відповіді (не питай власника)

- **Мова** коментарів і назв у UI — українська. Назва стилю — 1–2 слова.
- **Вигляд:** мінімалістично, як «Захід сонця»/«Аврора»: кілька відтінків акценту (`hue`, `s`, `hue_lo/hi`),
  дизеринг Байєра, світла тема (`light`) — своя палітра. Швидкодія — до ~4 мс на кадр 1920×1080 (cell 6).
- **Персонажі/бренди:** лише власні, без копій відомих персонажів, логотипів, ігор.
- **Застосовувати шпалери** користувачу самому не треба — лише додати в Налаштування. Перезапускати
  `pixel_wallpaper` лише якщо зараз активний саме твій стиль (`~/.cache/ignis/last_wallpaper.txt` = `pixel:<id>`).
- **Kiosk** (`kiosk/`, сесія kiosk) — ніколи не чіпати.
- **git / `sync_from_system.sh`** — робить лише Claude, коли обидва стани компілюються. Ти не комітиш.
  Закінчив — напиши в «Дошку» «готово: …», Claude перевірить і закомітить.
- Нічого не видаляти й не переписувати чуже, навіть якщо «можна краще».

## ЗАВДАННЯ 2 ДЛЯ agy: два нові стилі «за мотивами порталів» (після «Вежі»)

Настрій — як у порталах із воксельних ігор, але **власний процедурний ефект**: не копіювати й не відтворювати
текстури, кадри анімації чи палітри конкретної гри (Minecraft тощо), не називати стилі іменами з гри.
Нові `enum` / назви — в кінець списків, свої префікси буферів, правила вище.

1. **`riftportal` — «Розлом»:** вертикальна площина енергії на весь екран, крупні «пікселі»-блоки 1 клітинка,
   що повільно закручуються вихором (domain-warp шум + обертання), фіолетово-пурпурні відтінки від акценту,
   світлі прожилки, що течуть, дрібні частинки, які зриваються з поверхні й летять до глядача; рамка не потрібна.
   Світла тема — та сама енергія на світлому, «негативом» за яскравістю (`lt()`).
2. **`voidfield` — «Зоряна безодня»:** темна безодня з кількома шарами зірок/цяток на різній глибині, що
   зсуваються з паралаксом (ближні — швидше й більші), шари трохи різних відтінків акценту з бірюзово-зеленим
   (`hue_lo/hue_hi`), м'яке мерехтіння, легкий «туман» між шарами. Без жодних тайлових текстур.

Межі: ≤ 4 мс на кадр 1920×1080 (cell 6), обидві теми, постери ок, реєстрація в settings.py (`PIXEL_STYLES_WP`)
і welcome.cpp (`OPTS[]`). Закінчив — «готово: riftportal, voidfield» у Дошку. Питань власнику не став.
